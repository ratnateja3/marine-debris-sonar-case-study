AI-Powered Automated Underwater Marine Debris and Anomaly Detection System Using Side-Scan Sonar Imagery
Overview
This case study investigates deep-learning methods for analyzing side-scan sonar imagery. It combines a custom CNN for classifying annotated object crops with a pretrained YOLOv8n detector for locating objects in full images. An additional image-level screening experiment checks whether the detector predicts any of the known dataset classes. This screening is a known-class target-presence proxy, not open-set anomaly detection.
Dataset
Dataset: SSS-Marine-Debris-Detection on Roboflow Universe

Classes:
1. Fishing Gear or Crab Pot
2. Pipelines or Cylinders
3. ShipWrecks
The grouped dataset summary used in the final Phase 8 run reports 1,315 images, 1,632 annotated objects, and these image splits:
Split	Images	Annotated objects
Training	924	1,162
Validation	258	317
Test	133	153
Total	1,315	1,632


The dataset includes empty-label images that serve as background examples for object detection. Recording-group-aware splitting was used to reduce recording-related leakage. Perceptual-hash analysis identified residual near-duplicate candidates, so complete elimination of visual overlap is not claimed. Review the dataset's source page for its licence and attribution terms before redistributing data. The dataset itself is not included in this repository.
Methods
- CNN crop classification: annotated objects are converted to contextual square crops and resized to 128 × 128 pixels; a custom CNN predicts one of the three classes.
- YOLOv8n object detection: a pretrained YOLOv8n model is fine-tuned on full sonar images using 640-pixel inputs.
- Image-level screening: checks whether any known-class detection is present in an image; this is not a general unknown-anomaly detector.

Running the notebook
1. Open the notebook in Google Colab.
2. Mount Google Drive and update PROJECT_DIR and dataset paths if your folder layout differs.
3. Make sure the dataset has the expected YOLO images/ and labels/ structure and the data.yaml file.
4. Run cells in phase order. GPU availability is needed for practical YOLO training speed; a CPU runtime may be considerably slower.
5. For a fresh training run, use a new YOLO run-directory name or explicitly reuse a verified existing checkpoint rather than deleting previous results.
6. Run the final evaluation and Phase 8 summary cells, then confirm the reported metrics match the saved JSON files.
Limitations
- Residual near-duplicate candidates may remain across splits.
- Fishing Gear or Crab Pot detection recall is low.
- The CNN and YOLO models perform different tasks.
- The image-level screening only assesses presence of known classes; it does not demonstrate detection of previously unseen anomalies.
- The results are from this dataset and do not establish performance on independent sonar systems or operational marine surveys.
